`generation_quota_reservations` records one system-funded reservation per generation:

- Owner and UTC date.
- Reservation, consumption, and release timestamps.
- Foreign keys to the generation and authenticated owner.
- Timestamp/state consistency checks.
- Automatic deletion only if its parent generation or account is deleted.

Personal-key jobs never enter this table.

`reserve_openrouter_generation`:

- Takes the existing per-owner advisory lock.
- Returns an existing job for a repeated UUID.
- Preserves the 10-runs/hour and three-active-runs limits.
- Checks verified email inside the database.
- Serializes system-wide reservations for the UTC date.
- Enforces three combined image/video slots per owner/day.
- Enforces the configurable global system-funded limit.
- Inserts the job and quota reservation in the same transaction.

- `consume_generation_quota` converts an accepted reservation to consumed.
- `release_generation_quota` releases only a still-reserved request.
- Both update the job’s corresponding quota state.
- Anonymous and authenticated roles cannot execute these functions.

### Immutability trigger

`protect_generation_execution_identity` prevents later changes to:

- Funding source.
- UTC quota date.
- Resolved model.
- Endpoint tag.
- Capability snapshot.

### RLS policies

- Owners can read their own quota entries.
- Superadmins can read quota entries for diagnostics.
- No browser role receives insert, update, or delete access.
- All accounting mutations remain server-owned.

### Indexes

- `generation_quota_owner_day_state_idx`: allowance lookup.
- `generation_quota_identity_idx`: generation/owner/date identity.
- `generation_quota_day_state_idx`: global daily ceiling lookup.

## Why a webhook could be useful

A webhook is only useful for asynchronous video jobs:

1. We submit the video.
2. OpenRouter returns a job ID immediately.
3. Rendering continues on OpenRouter for several minutes.
4. When rendering finishes, OpenRouter calls our webhook.
5. Our server verifies the callback, fetches the authoritative job status, downloads the video, and saves it privately.

Benefits:

- The result can be ingested even after the user closes the page.
- Fewer repeated polling requests.
- Faster completion updates.
- Better behavior on serverless production deployments.

Images are synchronous, so they do not need webhooks.

## How the application works now

Webhooks are not currently required or enabled. Video uses persisted polling:

```text
Submit video
    ↓
Store OpenRouter job ID
    ↓
Show queued/processing result
    ↓
Browser polls every few seconds
    ↓
Refresh or reopen result later
    ↓
Server requests current OpenRouter status
    ↓
Download and validate completed MP4
    ↓
Save to private Supabase Storage
```

This is reliable because reopening the result never resubmits the generation. It continues from the existing OpenRouter job ID.

The limitation is that if the user closes the site, ingestion waits until the result is reopened. The OpenRouter job itself continues running.

## How a future webhook would work

The eventual implementation would add something like:

```text
POST /api/webhooks/openrouter
```

The endpoint would:

1. Read the exact raw request body.
2. Read OpenRouter’s timestamp and signature headers.
3. Reject callbacks older than five minutes.
4. Calculate an HMAC using `OPENROUTER_WEBHOOK_SECRET`.
5. Compare signatures using a timing-safe comparison.
6. Deduplicate the delivery identifier.
7. Locate the persisted generation using the OpenRouter job ID.
8. Ignore the callback’s claimed completion details.
9. Re-fetch status directly from OpenRouter.
10. Download through OpenRouter’s authenticated content endpoint.
11. Validate and privately ingest the MP4.
12. Safely accept duplicate deliveries without duplicating assets.

Re-fetching is important: the webhook is treated as a notification, not as authoritative generation data.

create or replace function public.reserve_system_generation(
  p_id uuid,
  p_owner uuid,
  p_provider text,
  p_model text,
  p_media text,
  p_prompt text,
  p_settings jsonb,
  p_capability_snapshot jsonb,
  p_global_daily_limit integer default 10
)
returns setof public.generation_jobs
language plpgsql
security definer
set search_path = public
as $$
declare
  v_quota_date date := (now() at time zone 'utc')::date;
  v_user_used integer;
  v_global_used integer;
begin
  if p_provider not in ('openrouter','huggingface') or p_media not in ('image','video')
    or p_global_daily_limit < 1 or p_global_daily_limit > 1000 then
    raise exception 'invalid_generation_configuration';
  end if;
  if p_provider = 'huggingface' and p_media <> 'image' then
    raise exception 'invalid_generation_configuration';
  end if;

  perform pg_advisory_xact_lock(hashtextextended(p_owner::text,0));
  if exists(select 1 from public.generation_jobs where id = p_id) then
    return query select * from public.generation_jobs where id = p_id and owner_id = p_owner;
    return;
  end if;

  if (select count(*) from public.generation_jobs where owner_id = p_owner and created_at > now() - interval '1 hour') >= 10
    or (select count(*) from public.generation_jobs where owner_id = p_owner and status::text in ('queued','processing','saving') and created_at > now() - interval '20 minutes') >= 3 then
    raise exception 'generation_limit';
  end if;
  if not exists(select 1 from auth.users where id = p_owner and email_confirmed_at is not null) then
    raise exception 'verified_email_required';
  end if;

  -- This lock string intentionally matches the existing OpenRouter reservation
  -- function so both providers serialize against the same shared quota ledger.
  perform pg_advisory_xact_lock(hashtextextended('openrouter-system:' || v_quota_date::text,0));
  select count(*) into v_user_used from public.generation_quota_reservations
    where owner_id = p_owner and quota_date = v_quota_date and state in ('reserved','consumed');
  if v_user_used >= 3 then raise exception 'daily_allowance_exhausted'; end if;
  select count(*) into v_global_used from public.generation_quota_reservations r
    join public.generation_jobs j on j.id = r.generation_id
    where r.quota_date = v_quota_date and r.state in ('reserved','consumed') and j.provider = p_provider;
  if v_global_used >= p_global_daily_limit then raise exception 'system_daily_limit'; end if;

  insert into public.generation_jobs(
    id,owner_id,provider,model,media_type,prompt,settings,status,
    funding_source,quota_date,quota_state,resolved_model,endpoint_tag,capability_snapshot
  ) values (
    p_id,p_owner,p_provider,p_model,p_media,p_prompt,p_settings,'queued',
    'system_free',v_quota_date,'reserved',p_model,
    case
      when p_provider = 'huggingface' then 'huggingface.textToImage'
      when p_media = 'video' then 'openrouter.videos.create'
      else 'openrouter.images.create'
    end,
    p_capability_snapshot
  );
  insert into public.generation_quota_reservations(generation_id,owner_id,quota_date,state)
    values (p_id,p_owner,v_quota_date,'reserved');
  return query select * from public.generation_jobs where id = p_id and owner_id = p_owner;
end $$;

create or replace function public.acquire_system_credential(
  p_generation uuid,
  p_provider text,
  p_media text,
  p_model text,
  p_lease_seconds integer default 300
)
returns table(credential_id uuid,lease_id uuid,attempt_number integer)
language plpgsql
security definer
set search_path = public
as $$
declare
  v_credential public.system_provider_credentials%rowtype;
  v_lease uuid;
  v_attempt integer;
begin
  if p_provider <> 'huggingface' or p_media <> 'image' or p_lease_seconds < 30 or p_lease_seconds > 900 then
    raise exception 'invalid_lease_request';
  end if;
  if not exists(select 1 from public.generation_jobs where id = p_generation and provider = p_provider and model = p_model and status::text in ('queued','processing')) then
    raise exception 'generation_not_leaseable';
  end if;

  update public.system_credential_leases
    set state = 'expired',released_at = now(),safe_error_code = 'lease_expired'
    where state = 'active' and expires_at <= now();
  update public.system_provider_credentials c set active_leases = (
    select count(*) from public.system_credential_leases l where l.credential_id = c.id and l.state = 'active'
  ) where c.provider = p_provider;

  select * into v_credential from public.system_provider_credentials c
    where c.provider = p_provider
      and c.status in ('active','cooldown')
      and (c.cooldown_until is null or c.cooldown_until <= now())
      and p_media = any(c.allowed_media)
      and p_model = any(c.allowed_models)
      and c.active_leases < c.max_concurrency
      and (c.usage_date <> (now() at time zone 'utc')::date or c.requests_used_today < c.request_limit_daily)
    order by c.priority desc,c.active_leases asc,c.last_selected_at asc nulls first,c.created_at asc
    for update skip locked limit 1;
  if v_credential.id is null then raise exception 'system_credential_unavailable'; end if;

  update public.system_provider_credentials set
    usage_date = (now() at time zone 'utc')::date,
    requests_used_today = case when usage_date = (now() at time zone 'utc')::date then requests_used_today + 1 else 1 end,
    active_leases = active_leases + 1,
    last_selected_at = now(),
    status = 'active',
    cooldown_until = null
    where id = v_credential.id;
  select coalesce(max(l.attempt_number),0) + 1 into v_attempt from public.system_credential_leases l where l.generation_id = p_generation;
  if v_attempt > 2 then raise exception 'provider_attempt_limit'; end if;
  insert into public.system_credential_leases(credential_id,generation_id,attempt_number,expires_at)
    values (v_credential.id,p_generation,v_attempt,now() + make_interval(secs => p_lease_seconds)) returning id into v_lease;
  update public.generation_jobs set system_credential_id = v_credential.id,provider_attempt_count = v_attempt
    where id = p_generation;
  return query select v_credential.id,v_lease,v_attempt;
end $$;

create or replace function public.settle_system_credential_lease(
  p_lease uuid,
  p_lease_state text,
  p_credential_status text default null,
  p_cooldown_seconds integer default null,
  p_safe_error_code text default null,
  p_success boolean default false
)
returns boolean
language plpgsql
security definer
set search_path = public
as $$
declare
  v_credential uuid;
  v_changed integer;
begin
  if p_lease_state not in ('completed','failed','ambiguous')
    or (p_credential_status is not null and p_credential_status not in ('active','cooldown','exhausted','invalid','disabled'))
    or (p_cooldown_seconds is not null and (p_cooldown_seconds < 1 or p_cooldown_seconds > 86400)) then
    raise exception 'invalid_lease_settlement';
  end if;
  select credential_id into v_credential from public.system_credential_leases where id = p_lease for update;
  if v_credential is null then return false; end if;
  update public.system_credential_leases set state = p_lease_state,released_at = now(),safe_error_code = p_safe_error_code
    where id = p_lease and state = 'active';
  get diagnostics v_changed = row_count;
  if v_changed = 0 then return false; end if;
  update public.system_provider_credentials set
    active_leases = greatest(0,active_leases - 1),
    status = case
      when status in ('draining','disabled','revoked') then status
      else coalesce(p_credential_status,status)
    end,
    cooldown_until = case
      when p_credential_status = 'cooldown' then now() + make_interval(secs => coalesce(p_cooldown_seconds,60))
      when p_credential_status is null then cooldown_until
      else null
    end,
    last_success_at = case when p_success then now() else last_success_at end,
    last_failure_at = case when p_success then last_failure_at else now() end,
    consecutive_failures = case when p_success then 0 else consecutive_failures + 1 end,
    validation_status = case when p_credential_status = 'invalid' then 'invalid' else validation_status end,
    validation_error_code = case when p_success then null else p_safe_error_code end
    where id = v_credential;
  return true;
end $$;

## What the migration adds

### Generation job columns

- `system_credential_id`: internal reference to the most recently leased system credential.
- `provider_attempt_count`: number of pool attempts made for the generation, bounded to ten at the table level and two by the leasing function.

### `system_provider_credentials`

Stores encrypted system credentials and scheduling state.

- `ciphertext`, `iv`, `auth_tag`: AES-GCM encrypted token material.
- `fingerprint`: prevents duplicate token insertion without storing plaintext.
- `last_four`: safe administrator identification.
- `provider_account_hash`: identifies tokens belonging to the same HF account without displaying the username.
- `status`: active, draining, cooling down, exhausted, invalid, disabled, or permanently revoked.
- `priority`: higher-priority credentials are selected first.
- `max_concurrency` and `active_leases`: prevent over-allocation.
- `allowed_media` and `allowed_models`: restrict credential capabilities.
- Validation fields record only safe status and error codes.
- Usage fields enforce a local per-token UTC daily attempt ceiling.
- Audit ownership fields record which superadmin created and updated it.
- Revocation requires encrypted secret fields to be erased.

### `system_credential_leases`

Records atomic credential allocation:

- The selected credential and generation.
- Attempt number.
- Active/completed/failed/expired/ambiguous state.
- Lease expiry and settlement timestamps.
- Sanitized failure code.

Only one active lease may exist for a generation.

### `provider_generation_attempts`

Stores safe execution diagnostics:

- Generation, credential, lease, model, and attempt number.
- Safe outcome and HTTP status.
- Provider request ID when available.
- Latency, sanitized usage, and reported cost.
- Acceptance and completion timestamps.

It never stores tokens, raw provider responses, prompts, or output URLs.

### Functions

- `reserve_system_generation`: atomically reserves the existing shared three-per-user allowance and provider-level daily ceiling.
- `acquire_system_credential`: reclaims expired leases, selects a compatible token with `FOR UPDATE SKIP LOCKED`, enforces concurrency and daily limits, and creates the lease.
- `settle_system_credential_lease`: releases the lease and updates cooldown, exhaustion, invalidation, or success health safely.

### Indexes

- Prevent multiple active leases for one generation.
- Accelerate compatible credential selection.
- Group tokens belonging to the same HF account.
- Find expired leases.
- Retrieve attempts by generation or credential.
- Retrieve jobs associated with a system credential.

### Security

RLS is enabled on all three new tables. No browser-facing policies are created deliberately. Table access and RPC execution are revoked from `anon` and `authenticated`; only the Supabase service role can read secrets, lease credentials, or write diagnostics.

The admin UI authenticates a superadmin first, then uses the server-only service-role data layer and returns only safe DTOs.

## How the pool works

1. A superadmin adds an authorized Hugging Face token.
2. The server validates it without generating media.
3. The token is encrypted before insertion into Supabase.
4. A user selects a Hugging Face model explicitly.
5. The application atomically reserves one of the user’s daily slots.
6. PostgreSQL leases a compatible healthy token.
7. The server decrypts that token only for the provider request.
8. Hugging Face returns the image.
9. The server validates its size, MIME signature, and dimensions.
10. The image is copied into owner-private Supabase Storage.
11. The lease and allowance are settled.
12. Safe diagnostics remain available to superadmins.

A timeout or ambiguous response is not retried because the provider may already have processed it.

returns trigger
language plpgsql
set search_path = public
